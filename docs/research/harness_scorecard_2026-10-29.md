# Harness trial scorecard

Updated: 2026-11-02
Scope: exploratory trials on the Pi gateway. This is an index of case results and receipts, **not an overall ranking**. The six-harness MCP and web-search lanes have run; compaction has candidate-specific exploratory evidence. Different fixtures, models, context windows, and policies are shown explicitly; compare only matching blocks.

## How to read a result

`Pass` means this run met its stated case checks. `Mixed` means both successful and failed checkpoints occurred. `Fail` means a required check failed. `Partial` means the run did not reach a decisive check. `Not run` means no evidence yet. A correct final answer cannot turn a failed compaction into a pass. Defaults and tuned policies have separate rows.

Each run should record: candidate version or commit, ready route and underlying model, actual context, native or tuned policy, output ceiling, number of complete and failed compactions, keyed facts retained, stop/overflow behavior, before/after ready roster, elapsed time, and raw receipt directory. Count completed compactions from a persisted summary or a successful native completion event, and name the evidence used in the case row. The companion `harness_scorecard_runs.csv` is the sortable run ledger; detailed interpretation stays in the linked trial notes.

## Frozen short control, 30B/32K

The [2026-11-02 shared-control trial](short_control_trial_2026-11-02.md) used one versioned three-turn fact/correction fixture, the same ready `gpu-rig/coder-30b` route, and an isolated workspace per run. Pi, OpenCode, and DeepSeek each passed three independent complete sessions with 9/9 current facts, no old values, and an unchanged ready roster. A fourth run for all three validated the final runner; DeepSeek also passed a separate self-contained-config check. This establishes a repeatable short-chat baseline, not compaction or overall quality. OpenCode's CLI lacks a dedicated finish event on many turns; those turns used exit 0 plus a final text event as weaker evidence.

The initial DeepSeek configuration failed the no-tools control on turn 1: it called `exit_plan_mode` twice before answering `ACK`. Explicitly disabling its `plan-mode` plugin fixed that setup error in a separately labeled rerun. Preserve the failed receipt. Per-harness controller extraction then passed one regression run each for Pi, DeepSeek, and OpenCode. Codex and Nanobot each passed one additional complete session on the same 30B/32K fixture. Hermes ran twice on its required separate 27B/65K route: both runs kept all nine facts but answered `ACK.` instead of exact `ACK` on turns 1–2, so both strict verdicts fail. Details and receipts are in the [short-control trial](short_control_trial_2026-11-02.md).
